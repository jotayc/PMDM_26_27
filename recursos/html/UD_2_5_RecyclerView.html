Rama UD_2_5_RecyclerView

RecyclerView

Una lista de películas, cada una con su cartel, su título y una descripción. Parece sencillo, pero detrás hay varias piezas que colaboran y una idea que ahorra muchísima memoria: reciclar las filas. Aquí vas a ver cada pieza por separado y después la lista funcionando por dentro.

En la rama UD_2_2 viste el Spinner con su adaptador: ya conoces la idea de que una vista no lleva los datos escritos, sino que se los da un adaptador. El RecyclerView usa esa misma idea, pero con filas que diseñas tú y con un truco para no gastar memoria.

2

El problema de las listas largas

Piensa en la lista de canciones de una aplicación de música: miles de canciones, cada una con su portada, su título y su artista. Cada fila de la pantalla es un pequeño layout con varias vistas dentro (una imagen y dos textos). Crear una vista cuesta memoria y tiempo.

La solución más ingenua sería crear una fila por cada canción. Pero en la pantalla del móvil solo caben unas pocas a la vez: las demás estarían ocupando memoria sin que nadie las vea.

La idea del RecyclerView

Solo existen las filas que se ven (y alguna más de reserva). Cuando una fila sale de la pantalla por arriba, no se destruye: se recicla, se le cambian los datos y entra por abajo mostrando otro elemento. De ahí el nombre: recycler, el que recicla.

Crear todas o reciclarmueve el control

Elige cuántos elementos tiene la lista y compara cuántas filas habría que crear con cada forma de hacerlo, en una pantalla donde caben unas cinco.

Las piezas y quién hace qué

Reciclar filas es más complicado que poner un texto con setText(), así que el trabajo se reparte entre varias piezas. Cada una tiene una única responsabilidad. Si entiendes qué hace cada una, el código deja de parecer un trabalenguas.

Explora las piezaspulsa cada una · 0 de 6
Pulsa una pieza para ver qué hace, en qué fichero está y con qué se puede comparar.
Una comparación que ayuda

Piensa en un restaurante con pocos platos. Los datos son el menú (lo que hay que servir). El molde es la forma del plato. El adaptador es la cocina: sabe cuántos platos hay que servir y qué va en cada uno. El ViewHolder es un plato concreto, ya fregado y listo para volver a usar. El RecyclerView es la mesa, donde solo caben unos cuantos a la vez, y el LayoutManager, el camarero que decide cómo colocarlos.

4

Los datos: el modelo Pelicula

Antes de pensar en la lista hay que decidir qué se va a mostrar de cada elemento. Eso es el modelo: una clase Java normal, como las que haces en Programación, con sus atributos, su constructor y sus getters. No sabe nada de Android ni de pantallas.

Models/Pelicula.java
public class Pelicula {

    private String titulo;
    private String descripcion;
    private int    imagenId;

    public Pelicula(String titulo, String descripcion, int imagenId) {
        this.titulo = titulo;
        this.descripcion = descripcion;
        this.imagenId = imagenId;
    }

    public String getTitulo() { return titulo; }
    public String getDescripcion() { return descripcion; }
    public int getImagenId() { return imagenId; }
    // ... y sus setters
}
¿Por qué la imagen es un int?

Las imágenes están en res/drawable/, y como cualquier recurso tienen su constante en la clase R: R.drawable.aqua es un número entero. El modelo guarda ese número, no la imagen. Cuando haga falta dibujarla, setImageResource() busca la imagen a partir del número.

Como todavía no sabes leer datos de una base de datos, la actividad los fabrica con un método auxiliar (TODO 10): crea seis objetos Pelicula, los mete en un ArrayList y lo devuelve.

Controllers/MainActivity.java
public static List<Pelicula> getListMovie() {
    ArrayList<Pelicula> list = new ArrayList<Pelicula>();
    list.add(new Pelicula("Aquaman", "Una vez se cansó de ser...", R.drawable.aqua));
    list.add(new Pelicula("Batman vs Superman", "Un hombre disfrazado...", R.drawable.batvssup));
    // ... cuatro películas más
    return list;
}

Cada objeto de esa lista será, más adelante, una fila. La posición en la lista (0, 1, 2…) es la que el RecyclerView usará para pedir los datos de cada fila.

5

El molde de la fila

Cada fila de la lista tiene el mismo aspecto: el cartel a la izquierda y, a la derecha, el título y la descripción. Ese aspecto se diseña una sola vez en un layout aparte, custom_item_list.xml. Es un molde: de él saldrán todas las filas.

res/layout/custom_item_list.xml (resumido)
<androidx.constraintlayout.widget.ConstraintLayout
    android:layout_width="match_parent"
    android:layout_height="wrap_content">

    <ImageView android:id="@+id/img_item" ... />
    <TextView  android:id="@+id/txt_item_tittle" ... />
    <TextView  android:id="@+id/txt_item_desc" ... />

</androidx.constraintlayout.widget.ConstraintLayout>
wrap_content de alto

La fila mide de alto lo que necesite su contenido (wrap_content). Si pusieras match_parent, cada fila ocuparía la pantalla entera y verías las películas de una en una.

En el layout de la actividad, en cambio, solo hay una vista: el propio RecyclerView (@+id/recView), ocupando toda la pantalla. Las filas no se escriben en él: las pondrá el adaptador en tiempo de ejecución.

6

El ViewHolder: una fila con sus vistas a mano

Para rellenar una fila hay que llegar a su imagen y a sus dos textos, y eso se hace con findViewById(). El problema es que buscar vistas cuesta tiempo, y en una lista que se desplaza habría que hacerlo cada vez que entra una fila.

El ViewHolder (literalmente, «el que sostiene las vistas») resuelve eso: es un objeto que acompaña a cada fila y que guarda, ya encontradas, las referencias a sus vistas. Se buscan una sola vez, al crear la fila. Después, por muchas veces que se recicle, solo hay que usar esas referencias.

Adapters/RecyclerAdapter.java · TODO 2 y 3
public class RecyclerHolder extends RecyclerView.ViewHolder {
    ImageView imgPelicula;
    TextView  txtViewTitle;
    TextView  txtViewDesc;

    public RecyclerHolder(@NonNull View itemView) {
        super(itemView);
        imgPelicula  = (ImageView) itemView.findViewById(R.id.img_item);
        txtViewTitle = (TextView)  itemView.findViewById(R.id.txt_item_tittle);
        txtViewDesc  = (TextView)  itemView.findViewById(R.id.txt_item_desc);
    }
}
itemView.findViewById, no findViewById a secas

En una actividad escribías findViewById() y buscaba en toda la pantalla. Aquí cada fila es un trozo de pantalla distinto, y hay que buscar dentro de esa fila: por eso se llama sobre itemView, la vista de la fila que recibe el constructor. Todas las filas tienen un img_item; lo que importa es el de esta.

La clase está escrita dentro del adaptador (es una clase interna), porque solo el adaptador la usa.

7

El adaptador: tres preguntas que le hace la lista

El adaptador hereda de RecyclerView.Adapter y le dice entre los signos < > qué ViewHolder usa. Recibe la lista de películas en su constructor y la guarda.

Adapters/RecyclerAdapter.java · TODO 4
public class RecyclerAdapter extends RecyclerView.Adapter<RecyclerAdapter.RecyclerHolder> {
    List<Pelicula> listMovies;

    public RecyclerAdapter(List<Pelicula> listMovies) {
        this.listMovies = listMovies;
    }
    ...
}

Lo más importante de este apartado: tú no llamas a ninguno de sus métodos. Los llama el RecyclerView, cuando los necesita, como si le hiciera preguntas al adaptador. Hay tres:

Lo que pregunta el RecyclerViewMétodo que respondeCuándo se llama
«¿Cuántos elementos hay?»getItemCount()Al empezar y cada vez que necesita saber hasta dónde llega la lista.
«No tengo ninguna fila libre: ¿me fabricas una?»onCreateViewHolder()Solo cuando hace falta una fila y no hay ninguna para reciclar. Pocas veces.
«Rellena esta fila con el elemento número 4»onBindViewHolder()Cada vez que una fila va a mostrar un elemento, sea nueva o reciclada. Muchísimas veces.

7.1getItemCount(): cuántos hay

Adapters/RecyclerAdapter.java · TODO 8
@Override
public int getItemCount() {
    return listMovies.size();
}

Parece una tontería, pero si devolviera 0 la lista saldría vacía aunque haya películas: el RecyclerView pensaría que no hay nada que mostrar.

7.2onCreateViewHolder(): fabricar una fila

Convierte el molde XML en una fila de verdad y le pone su ViewHolder. A convertir un XML en objetos View se le llama inflar.

Adapters/RecyclerAdapter.java · TODO 5 y 6
@NonNull
@Override
public RecyclerHolder onCreateViewHolder(@NonNull ViewGroup parent, int viewType) {
    View view = LayoutInflater.from(parent.getContext())
            .inflate(R.layout.custom_item_list, parent, false);
    RecyclerHolder recyclerHolder = new RecyclerHolder(view);
    return recyclerHolder;
}
Del molde a la filapaso 1 de 4

1. El molde es texto. R.layout.custom_item_list apunta al fichero XML. Un XML no se puede dibujar ni tocar desde Java: son solo etiquetas.

<ImageView android:id="@+id/img_item" />
<TextView  android:id="@+id/txt_item_tittle" />
<TextView  android:id="@+id/txt_item_desc" />

2. Se infla. LayoutInflater.inflate() lee el XML y crea los objetos de verdad: un ConstraintLayout con un ImageView y dos TextView dentro. El resultado es una View: la fila.

LayoutInflater.from(parent.getContext()) consigue el inflador a partir del contexto de la lista (parent es el propio RecyclerView).

3. El false del final. El tercer parámetro de inflate() pregunta: «¿meto ya esta fila dentro de parent?». La respuesta es no: el RecyclerView la colocará él mismo cuando le toque, donde diga el LayoutManager. parent se pasa solo para que la fila sepa qué medidas tendrá.

Si pones true

La aplicación se cierra con un error, porque la fila acabaría metida en la lista dos veces: una por inflate() y otra por el RecyclerView.

4. Se envuelve en un ViewHolder. new RecyclerHolder(view) busca en esa fila sus tres vistas y se las guarda (apartado 6). El método devuelve el ViewHolder, y el RecyclerView se queda con él para siempre: a partir de ahora lo irá reciclando.

7.3onBindViewHolder(): rellenar una fila

Recibe una fila (su ViewHolder) y una posición, y pone en la fila los datos de la película que está en esa posición de la lista. Como el ViewHolder ya tiene las vistas a mano, rellenar es inmediato:

Adapters/RecyclerAdapter.java · TODO 7
@Override
public void onBindViewHolder(@NonNull RecyclerHolder holder, int position) {
    Pelicula pelicula = listMovies.get(position);
    holder.txtViewDesc.setText(pelicula.getDescripcion());
    holder.txtViewTitle.setText(pelicula.getTitulo());
    holder.imgPelicula.setImageResource(pelicula.getImagenId());
}
Una fila reciclada trae los datos de antes

Cuando una fila se recicla, todavía muestra la película anterior. onBindViewHolder() tiene que sobrescribir todas sus vistas. Si te dejas una (por ejemplo, la imagen), al desplazar verás títulos nuevos con carteles de otras películas.

    Montar la lista en la actividad

    Con el modelo, el molde, el ViewHolder y el adaptador hechos, la actividad solo tiene que juntar las piezas. Son cuatro líneas, pero cada una hace falta:

    Controllers/MainActivity.java · TODO 1, 9, 11 y 12
    RecyclerView recyclerView;
RecyclerAdapter recAdapter;

// dentro de onCreate(), después de setContentView()
recyclerView = (RecyclerView) findViewById(R.id.recView);
recAdapter = new RecyclerAdapter(getListMovie());

LinearLayoutManager layoutManager = new LinearLayoutManager(this);

recyclerView.setAdapter(recAdapter);
recyclerView.setLayoutManager(layoutManager);
    1. Se busca el RecyclerView del layout, como cualquier otra vista.
    2. Se crea el adaptador y se le pasa la lista de películas.
    3. Se crea el LayoutManager, que decide la disposición. LinearLayoutManager pone las filas una debajo de otra.
    4. Se le dan al RecyclerView el adaptador y el LayoutManager. Sin cualquiera de los dos, la lista no muestra nada.
    Monta la listaquita y pon piezas

    Marca y desmarca líneas del código y mira qué pasa en el móvil y en Logcat, la ventana de Android Studio donde aparecen los mensajes de la aplicación.

    LayoutManager:

    Películas
    LayoutManagerCómo coloca las filasSe crea con
    Lineal verticalUna debajo de otra (el de la rama)new LinearLayoutManager(this)
    Lineal horizontalUna al lado de otra, desplazando a los ladosnew LinearLayoutManager(this, LinearLayoutManager.HORIZONTAL, false)
    RejillaEn columnas, como la galería de fotosnew GridLayoutManager(this, 2)

    Fíjate en que para cambiar de lista a rejilla no se toca el adaptador ni el molde: solo el LayoutManager. Cada pieza hace una sola cosa, y por eso se pueden cambiar por separado.

    Pruébalo

    1. Ejecuta la aplicación (Run). Verás las seis películas, cada una con su cartel, su título y su descripción.
    2. Desplaza la lista arriba y abajo. En un móvil grande puede que quepan todas y no haya desplazamiento: gira el emulador para tener menos alto.
    3. Añade en onCreateViewHolder() y en onBindViewHolder() una línea Log.d("RV", "create"); y Log.d("RV", "bind " + position);. Filtra Logcat por RV y desplaza: comprueba lo que viste en el simulador.
    4. Copia diez veces las líneas list.add(...) para tener muchas películas y repite: el número de create casi no cambia; el de bind, sí.
    5. Cambia el LinearLayoutManager por new GridLayoutManager(this, 2) y ejecuta. Sin tocar nada más, la lista pasa a ser una rejilla.

    Errores comunes

    Lo que pasaPor qué
    La pantalla sale en blanco, sin ningún error. En Logcat: No layout manager attached; skipping layoutFalta setLayoutManager(). Sin LayoutManager, el RecyclerView no sabe dónde poner las filas y no pone ninguna.
    La pantalla sale en blanco. En Logcat: No adapter attached; skipping layoutFalta setAdapter().
    La pantalla sale en blanco y no hay ningún avisogetItemCount() devuelve 0, o la lista que recibe el adaptador está vacía.
    Cada película ocupa la pantalla enteraLa fila mide match_parent de alto en custom_item_list.xml. Tiene que ser wrap_content.
    La aplicación se cierra al abrir la lista, con IllegalStateException sobre un hijo que ya tiene padreEn inflate() se ha puesto true como tercer parámetro (apartado 7.2).
    NullPointerException al rellenar una filaEn el ViewHolder se ha buscado un id que no está en custom_item_list.xml, y la referencia vale null.
    Al desplazar, aparecen carteles de otras películasonBindViewHolder() no rellena todas las vistas de la fila: se queda lo que tenía la fila reciclada.

    Para practicar

    Hazlo en tu propia rama para no modificar la del tema: git switch -c mio/UD_2_5_RecyclerView.

    1. Añade a Pelicula un atributo anio y muéstralo en la fila, debajo del título. Tendrás que tocar el modelo, el molde, el ViewHolder y onBindViewHolder(): comprueba que entiendes por qué los cuatro.
