Button: dos formas de atender un clic

Dos botones y un texto. La misma pantalla se puede programar de dos maneras: con una clase anónima para cada botón o haciendo que la actividad atienda todos los clics en un único método.

2

Conceptos

2.1Las dos formas

Para que un botón responda al clic hay que darle un objeto que implemente la interfaz View.OnClickListener. Ese objeto puede ser de dos tipos:

Forma 1: clase anónimaForma 2: la actividad
Dónde va el códigoJunto a cada botón, en onCreate()En un único método onClick() de la actividad
Qué se pasa al botónnew View.OnClickListener() { … }this
Cuándo convienePocos botones, cada uno con una acción distintaMuchos botones, o acciones parecidas que conviene tener juntas

2.2La actividad como listener

Al escribir implements View.OnClickListener en la cabecera de la clase, la actividad se compromete a tener el método public void onClick(View view): si falta, el código no compila. A partir de ahí la actividad es un listener, y por eso se le puede pasar a los botones con setOnClickListener(this).

MainActivity.java
public class MainActivity extends AppCompatActivity implements View.OnClickListener {

    // ...

    //Implementación del método onClick de la interfaz OnClickListener (forma 2)
    @Override
    public void onClick(View view) {
        Button btn = (Button) view;

        if (btn.getId() == R.id.btn_show) {
            this.btn_show.setText("Un saludo");
        } else if (btn.getId() == R.id.btnHide) {
            this.btn_show.setText("Adios");
        }
    }
}

@Override indica que el método viene de la interfaz: es una implementación (sobrescritura), no una sobrecarga.

2.3Qué botón se ha pulsado

El parámetro view es la vista que se ha pulsado. Su método getId() devuelve su id, que se compara con las constantes de R.id. getId() existe en cualquier View, así que el cast a Button no es necesario: bastaría con view.getId().

¿Por qué if / else if y no un switch?

Un case de switch necesita una constante, y en los proyectos Android actuales los ids de R ya no lo son. Este switch no compila:

No compila
switch (view.getId()) {
    case R.id.btn_show:   // error: constant expression required
        ...
}

Por eso se compara con if / else if.

2.4Un botón, un solo listener

Un botón guarda un único listener de clic. Si llamas dos veces a setOnClickListener(), el segundo sustituye al primero:

Por eso, en el código, la forma 1 está comentada: si se activara, como va después de la forma 2, sería la que quedaría.

El código paso a paso

Abre la ventana TODO (View → Tool Windows → TODO) y sigue los comentarios del 1 al 6.

TODO 1onCreate(): el punto de partida

Primer método que Android llama al crear la actividad. Aquí se prepara todo lo que la pantalla necesita.

MainActivity.java
@Override
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    ...
}

TODO 2Declarar los objetos

Tres atributos: los dos botones y el TextView. Se declaran fuera de los métodos para usarlos desde onCreate() y desde onClick().

MainActivity.java
private Button btn_show;
private Button btn_hide;
private TextView txt_view;

TODO 3Conectar el layout con la actividad

setContentView() carga el layout y crea sus vistas. Va antes de buscar ninguna vista.

MainActivity.java
setContentView(R.layout.activity_main);

TODO 4Inicializar los objetos

findViewById() busca cada vista por su id. Fíjate en que el id del segundo botón es btnHide y el atributo Java se llama btn_hide: no tienen por qué coincidir, pero hacerlos iguales evita confusiones.

MainActivity.java
this.btn_show = (Button) findViewById(R.id.btn_show);
this.btn_hide = (Button) findViewById(R.id.btnHide);
this.txt_view = (TextView) findViewById(R.id.txt_view);

TODO 5Las dos formas de atender el clic

La forma 2 está activa: los dos botones reciben this. Debajo está la forma 1 comentada, que haría lo mismo con una clase anónima por botón. La pulsación larga usa una clase anónima.

MainActivity.java
// Forma 2 (activa)
this.btn_show.setOnClickListener(this);
this.btn_hide.setOnClickListener(this);

// Forma 1 (comentada en el código)
// this.btn_show.setOnClickListener(new View.OnClickListener() {
//     @Override
//     public void onClick(View view) {
//         btn_show.setText("Un saludo");
//     }
// });
// ... y lo mismo para btn_hide con "Adios"

// Pulsación larga: clase anónima
this.btn_show.setOnLongClickListener(new View.OnLongClickListener() {
    @Override
    public boolean onLongClick(View view) {
        txt_view.setText("Esto es una pulsación larga");
        return true;
    }
});

TODO 6Los métodos del ciclo de vida

Android los llama automáticamente en cada cambio de estado. Aquí están vacíos: solo llaman a super.

MainActivity.java
@Override
protected void onStart() {
    super.onStart();
}
// ... onResume(), onPause(), onStop(), onDestroy()
4

El layout

Un TextView en el centro y dos botones debajo, uno junto al otro (se omiten layout_width y layout_height, que valen wrap_content):

res/layout/activity_main.xml
<Button
    android:id="@+id/btn_show"
    android:text="Saludar"
    app:layout_constraintStart_toStartOf="parent"
    app:layout_constraintEnd_toEndOf="parent"
    app:layout_constraintHorizontal_bias="0.215"
    app:layout_constraintTop_toBottomOf="@+id/txt_view"
    app:layout_constraintBottom_toBottomOf="parent"
    app:layout_constraintVertical_bias="0.503" />

<Button
    android:id="@+id/btnHide"
    android:text="Despedir"
    android:layout_marginEnd="51dp"
    app:layout_constraintEnd_toEndOf="parent"
    app:layout_constraintTop_toTopOf="@+id/btn_show"
    app:layout_constraintBottom_toBottomOf="@+id/btn_show" />
AtributoQué hace
constraintHorizontal_bias="0.215"El botón «Saludar» está anclado a los dos lados, pero se coloca más cerca de la izquierda (0 = izquierda, 1 = derecha).
constraintTop_toTopOf / Bottom_toBottomOf="@+id/btn_show"El botón «Despedir» se alinea verticalmente con «Saludar».
layout_marginEnd="51dp"Deja 51 dp de separación con el borde derecho.
dp

Los tamaños en Android se dan en dp (píxeles independientes de la densidad): 51 dp ocupan lo mismo a la vista en una pantalla de baja resolución que en una de alta.

5

Pruébalo

  1. Ejecuta la aplicación: verás «Hello World!» y los botones «Saludar» y «Despedir».
  2. Pulsa «Saludar»: el propio botón pasa a llamarse «Un saludo».
  3. Pulsa «Despedir»: el botón «Saludar» pasa a llamarse «Adios». Desde un listener se puede cambiar cualquier vista, no solo la pulsada.
  4. Mantén pulsado «Saludar»: cambia el texto central.
  5. Comenta la forma 2, descomenta la forma 1 y vuelve a ejecutar: todo funciona igual.

Errores comunes

Lo que pasaPor qué
setOnClickListener(this) se marca en rojoFalta implements View.OnClickListener en la cabecera: la actividad no es un listener.
La clase se marca en rojo tras añadir implementsFalta el método public void onClick(View view). Alt+Intro → Implement methods lo crea.
Un botón no hace nadaNo se ha llamado a setOnClickListener(this) para ese botón, o su id no aparece en ningún if de onClick().
Constant expression requiredSe ha usado un switch con case R.id… (apartado 2.3).
Tras activar la forma 1, el onClick() de la actividad deja de ejecutarseLa forma 1 sustituye a la 2: cada botón guarda un solo listener (apartado 2.4).
