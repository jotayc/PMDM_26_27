Rama UD_2_9_floating_menu

Menú contextual flotante

Mantienes pulsado un botón y aparece junto al dedo un menú con opciones para ese botón. Con esta rama verás cómo se le dice a Android qué vista tiene menú y qué métodos se llaman al abrirlo, al elegir y al cerrarlo.

Violeta: simuladores; se manejan con los botones. En su registro, verde es un método al que llama Android y naranja, lo que hace tu código.
Azul: lo que debes conocer aunque no se use en la rama.
Ámbar: un consejo para no equivocarte.
1

Qué vas a aprender

Registrar la vistaDecirle a Android qué vista tiene menú contextual.
Pulsación largaEl gesto que abre el menú, junto al dedo.
Crear y responderLos dos métodos que crean las opciones y atienden la elegida.
Saber cuándo se cierraUn tercer método que se llama siempre que el menú desaparece.

Al mantener pulsado el botón Menu flotante aparece una lista de colores, y al elegir uno, el botón cambia a ese color.

2

Conceptos

2.1Un menú para un elemento concreto

Un menú contextual ofrece opciones sobre un elemento de la pantalla, no sobre la pantalla entera. Se abre al mantener pulsado ese elemento, y lo llamamos flotante porque aparece sobre la pantalla, junto al dedo, como una pequeña ventana.

Mientras no se mantiene pulsado, el menú no se ve ni ocupa sitio.

2.2El recorrido, paso a paso

Tu código solo da una orden: registrar la vista. Todo lo demás lo inicia Android, que va llamando a los métodos que has escrito según lo que hace el usuario.

Abre el menú contextualmira qué métodos se llaman

Mantén pulsado Menu flotante en el móvil o usa el botón de la derecha. Prueba también a quitar el registro. El aspecto es aproximado.

MainActivity
registerForContextMenu(btn_floating): sí
El botón está registrado: una pulsación larga abrirá el menú.
    MétodoCuándo lo llama AndroidPara qué
    onCreateContextMenu()Cada vez que se abre el menúCrear las opciones a partir del XML.
    onContextItemSelected()Al elegir una opciónHacer lo que corresponda.
    onContextMenuClosed()Al cerrarse, se haya elegido o noReaccionar al cierre. Es opcional.
    Sin registro no hay menú, y tampoco hay error

    Si olvidas registerForContextMenu(), todo compila y la aplicación funciona, pero la pulsación larga no hace nada. Es lo primero que hay que mirar cuando el menú no aparece.

    2.3Qué parte del XML se usa

    El menú se define en res/menu/floating_menu.xml con elementos <item>. No todo lo que admite un <item> tiene efecto aquí:

    AtributoEn un menú flotante
    android:idSí: sirve para saber qué opción se ha pulsado.
    android:titleSí: es el texto de la opción.
    android:iconNo se ve: las opciones aparecen solo con su texto.
    app:showAsActionNo tiene efecto: indica cómo colocar una opción en una barra, y aquí no hay barra.
    Por qué están en este XML

    El fichero lleva iconos y app:showAsAction, aunque no cambien nada. Al ejecutar la aplicación comprobarás que solo se ven los textos. Es un buen ejemplo de que un atributo puede ser correcto y no tener ningún efecto en ese tipo de menú.

    3

    El código paso a paso

    Abre la ventana TODO (View → Tool Windows → TODO): los comentarios van numerados del 1 al 6, y todos están en MainActivity.

    TODO 1Registrar la vista

    Una sola línea en onCreate(), con la vista que tendrá el menú.

    MainActivity.java
    registerForContextMenu(btn_floating);

    TODO 2-3Crear el menú

    El método es de la actividad, no de la vista, y Android le pasa el menú vacío y la vista que se ha pulsado. Se llena con un inflater, que crea las opciones a partir del XML. El título del menú se pone desde el código.

    MainActivity.java
    @Override
public void onCreateContextMenu(ContextMenu menu, View v, ContextMenu.ContextMenuInfo menuInfo) {
    super.onCreateContextMenu(menu, v, menuInfo);

    getMenuInflater().inflate(R.menu.floating_menu,menu);
    menu.setHeaderTitle("Menu flotante");
}

    TODO 4-5Responder a la opción

    Se compara el id de la opción con los del XML, con if, y se cambia el color del botón. Devolver true indica que la opción ya está atendida.

    MainActivity.java
    @Override
public boolean onContextItemSelected(@NonNull MenuItem item) {
    int itemId = item.getItemId();
    if (itemId == R.id.fl_blue) {
        btn_floating.setBackgroundColor(Color.BLUE);
    } else if (itemId == R.id.fl_green) {
        btn_floating.setBackgroundColor(Color.GREEN);
    } else if (itemId == R.id.fl_red) {
        btn_floating.setBackgroundColor(Color.RED);
    }

    return true;
}

    TODO 6Saber que se ha cerrado

    Este método es opcional. Aquí muestra un Toast, y así puedes comprobar que se llama tanto si eliges una opción como si tocas fuera.

    MainActivity.java
    @Override
public void onContextMenuClosed(@NonNull Menu menu) {
    myToast("Menu cerrado");
}

    El menú y el layout

    El fichero del menú, en la carpeta res/menu/:

    res/menu/floating_menu.xml
    <menu xmlns:app="http://schemas.android.com/apk/res-auto"
    xmlns:android="http://schemas.android.com/apk/res/android">

    <item
        android:id="@+id/fl_blue"
        android:icon="@drawable/color_blue"
        android:title="Azul"
        app:showAsAction="ifRoom|withText" />
    <item
        android:id="@+id/fl_green"
        android:icon="@drawable/color_green"
        android:title="Verde"
        app:showAsAction="never" />
    <item
        android:id="@+id/fl_red"
        android:icon="@drawable/color_red"
        android:title="Rojo" />
</menu>

    El layout tiene dos botones, btn_floating y btn_action.

    El botón Action Menu no hace nada en esta rama

    Solo tiene un menú el botón que se ha registrado. El otro botón y el fichero action_menu.xml pertenecen al menú de acción, que es otro tipo de menú y se trabaja en la rama UD_2_8_action_menu.

    5

    Pruébalo

    1. Ejecuta la aplicación (Run) y haz un clic corto en Menu flotante. No ocurre nada.
    2. Ahora mantenlo pulsado. Aparece el menú junto al dedo, con su título y tres colores, sin iconos.
    3. Elige Verde. El botón cambia de color y aparece el Toast «Menu cerrado».
    4. Abre el menú otra vez y toca fuera. No cambia el color, pero el Toast aparece igualmente.
    5. Mantén pulsado Action Menu. No ocurre nada: esa vista no está registrada.
    6. Comenta la línea de registerForContextMenu() y vuelve a ejecutar. No hay ningún error, pero el menú ya no se abre.
    6

    Errores comunes

    Lo que pasaPor qué
    La pulsación larga no hace nadaFalta registerForContextMenu(), o se ha registrado otra vista.
    El menú aparece vacíoFalta inflate() en onCreateContextMenu().
    Las opciones no hacen nadaSe ha escrito onOptionsItemSelected(), que es el de la barra de app. El del menú contextual es onContextItemSelected().
    Al usar R.id... en un switch no compilaLos id de los recursos no son constantes: se comparan con if.
    Los iconos del XML no se venEs lo esperado en este menú (apartado 2.3).
    @Override marca error en el métodoEl nombre o los parámetros no coinciden con los del método original. Deja que lo genere Android Studio: Code → Override Methods.

    Para practicar

    Hazlo en tu propia rama para no modificar la del tema: git switch -c mio/UD_2_9.

    1. Pasa a strings.xml los títulos de las opciones y el título del menú.
    2. Añade una cuarta opción que devuelva el botón a su color original.
    3. Quita los atributos que no tienen efecto en este menú y comprueba que todo sigue igual.
    4. Registra también btn_action. Observa que los dos botones abren el mismo menú, pero solo cambia de color uno.
    5. Usa el parámetro v de onCreateContextMenu() para que cada botón tenga un título distinto (v.getId()).
    6. Haz que la opción elegida cambie el color del botón que se pulsó, sea cual sea. Necesitarás guardar esa vista en un atributo.
