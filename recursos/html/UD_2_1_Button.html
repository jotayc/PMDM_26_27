Rama UD_2_1_Button

Button

Una pantalla con un texto y un botón que lo cambia al pulsarlo. Con ella verás cómo se conecta el diseño XML con el código Java y cómo se responde a lo que hace el usuario.

1

Qué vas a aprender

TextView y ButtonLas dos vistas más básicas: mostrar un texto y un botón que se puede pulsar.
Layout ↔ actividadMostrar el layout con setContentView() y obtener sus vistas con findViewById().
EventosResponder a una pulsación corta y a una larga con listeners.
Clases anónimas y lambdasImplementar una interfaz sin crear una clase aparte.
strings.xmlPor qué los textos no se escriben directamente en el código.

2.3Pulsación corta y pulsación larga

Un botón puede tener un listener para cada tipo de toque: setOnClickListener() para la pulsación corta y setOnLongClickListener() para la larga.

2.4Interfaces, clases anónimas y lambdas

View.OnClickListener es una interfaz con un único método, onClick(View view). El botón acepta cualquier objeto que la implemente. En lugar de crear una clase aparte solo para eso, se usa una clase anónima: una clase sin nombre que se declara y se instancia en el mismo sitio.

Desde Java 8, cuando una interfaz tiene un solo método se puede escribir lo mismo de forma más corta con una lambda:

Con clase anónima (como en esta rama)
this.btn_show.setOnClickListener(new View.OnClickListener() {

    @Override
    public void onClick(View view) {
        txt_view.setText("Hola 2DAM");
    }
});
Con lambda (equivalente)
this.btn_show.setOnClickListener(view -> txt_view.setText("Hola 2DAM"));

this.btn_show.setOnLongClickListener(view -> {
    txt_view.setText("Esto es una pulsación larga");
    return true;
});

Las dos versiones hacen exactamente lo mismo. view es el parámetro de onClick(): la vista que se ha pulsado.

2.5Los textos van en strings.xml

En esta rama los textos ("Hola 2DAM", "Button"…) están escritos directamente en el código y en el layout, y Android Studio lo marca con un aviso. Lo correcto es guardarlos en res/values/strings.xml, cada uno con un nombre:

res/values/strings.xml
<resources>
    <string name="app_name">PMDM</string>
    <string name="saludo">Hola 2DAM</string>
</resources>
En el layoutandroid:text="@string/saludo"
En Javatxt_view.setText(R.string.saludo);

Así los textos se cambian en un solo sitio y la aplicación se puede traducir a otros idiomas sin tocar el código.

3

El código paso a paso

Abre la ventana TODO (View → Tool Windows → TODO): los comentarios aparecen numerados del 1 al 6. Síguelos en ese orden.

TODO 1onCreate(): el punto de partida

Es el primer método que Android llama al crear la actividad. Todo lo que la pantalla necesita para funcionar se prepara aquí. Siempre empieza llamando a super.onCreate().

MainActivity.java
@Override
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    ...
}

TODO 2Declarar los objetos

Se declaran como atributos de la clase, fuera de cualquier método, para poder usarlos desde onCreate() y desde los listeners. Aquí solo se declaran: todavía valen null.

MainActivity.java
private Button btn_show;
private TextView txt_view;

TODO 3Conectar el layout con la actividad

setContentView() carga el layout y crea todas sus vistas. Tiene que ir antes de buscar ninguna vista.

MainActivity.java
setContentView(R.layout.activity_main);

TODO 4Inicializar los objetos

findViewById() busca en el layout la vista con ese id y la devuelve. A partir de aquí, btn_show y txt_view son las vistas reales de la pantalla. El cast (Button) ya no es obligatorio: findViewById() devuelve el tipo adecuado.

MainActivity.java
this.btn_show = (Button) findViewById(R.id.btn_show);
this.txt_view = (TextView) findViewById(R.id.txt_view);

TODO 5Listeners de clic y de pulsación larga

Cada listener se implementa con una clase anónima (apartado 2.4). En onClick() se cambia el texto; en onLongClick() también, y se devuelve true para indicar que el evento está atendido (apartado 2.3).

MainActivity.java
this.btn_show.setOnClickListener(new View.OnClickListener() {
    @Override
    public void onClick(View view) {
        txt_view.setText("Hola 2DAM");
    }
});

this.btn_show.setOnLongClickListener(new View.OnLongClickListener() {
    @Override
    public boolean onLongClick(View view) {
        txt_view.setText("Esto es una pulsación larga");
        return true;
    }
});

TODO 6Los métodos del ciclo de vida

Android los llama automáticamente cuando la actividad cambia de estado. En esta rama están vacíos: solo llaman a super. Sirven para ver en qué orden se ejecutan (apartado «Para practicar»).

MainActivity.java
@Override
protected void onStart() {
    super.onStart();
}
// ... onResume(), onPause(), onStop(), onDestroy()
4

El layout

El layout tiene dos vistas dentro de un ConstraintLayout:

res/layout/activity_main.xml
<TextView
    android:id="@+id/txt_view"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Hello World!"
    app:layout_constraintBottom_toBottomOf="parent"
    app:layout_constraintLeft_toLeftOf="parent"
    app:layout_constraintRight_toRightOf="parent"
    app:layout_constraintTop_toTopOf="parent" />

<Button
    android:id="@+id/btn_show"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Button"
    app:layout_constraintBottom_toBottomOf="parent"
    app:layout_constraintEnd_toEndOf="parent"
    app:layout_constraintStart_toStartOf="parent"
    app:layout_constraintTop_toBottomOf="@+id/txt_view"
    app:layout_constraintVertical_bias="0.52" />
AtributoQué hace
android:id="@+id/…"Da nombre a la vista. El + indica que se crea el id. Es lo que usa findViewById().
wrap_contentLa vista mide lo justo para su contenido.
android:textEl texto que muestra al empezar.
…constraintTop_toBottomOf="@+id/txt_view"El botón se coloca debajo del TextView.
…constraintVertical_bias="0.52"Entre sus dos anclajes verticales, el botón se coloca un poco por debajo de la mitad (0 sería arriba del todo; 1, abajo).
Left/Right o Start/End

El TextView usa Left/Right y el botón Start/End. Hacen lo mismo en idiomas que se leen de izquierda a derecha; Start/End es lo recomendado, porque se invierte solo en idiomas como el árabe.

5

Pruébalo

  1. Ejecuta la aplicación (Run). Verás «Hello World!» y un botón debajo.
  2. Pulsa el botón: el texto cambia a «Hola 2DAM».
  3. Mantén pulsado el botón: el texto cambia a «Esto es una pulsación larga».
  4. Gira el móvil o el emulador: el texto vuelve a «Hello World!».
¿Por qué vuelve el texto al girar?

Al girar, Android destruye la actividad y la crea de nuevo (onDestroy() y otra vez onCreate()). El layout se carga desde cero con su texto inicial. Es el ciclo de vida en acción.

6

Errores comunes

Lo que pasaPor qué
La aplicación se cierra al abrirla, con NullPointerException en LogcatfindViewById() está antes de setContentView(), o el id no coincide con el del layout: devuelve null.
Pulsas el botón y no pasa nadaNo se ha llamado a setOnClickListener(), o se ha registrado en otra vista.
Tras una pulsación larga, el texto cambia dos vecesonLongClick() devuelve false, así que al soltar también se ejecuta onClick().
Cannot resolve symbol 'R'Hay un error en algún XML de res/ y Android no ha podido generar la clase R. Revisa la ventana Build.
Aviso amarillo «Hardcoded string»El texto está escrito directamente en lugar de en strings.xml (apartado 2.5).

Para practicar

Hazlo en tu propia rama para no modificar la del tema: git switch -c mio/UD_2_1_Button.

  1. Pasa los tres textos («Hello World!», «Button» y «Hola 2DAM») a strings.xml y úsalos desde el layout y desde el código.
  2. Reescribe los dos listeners con lambdas.
  3. Añade un segundo botón «Borrar» que deje el TextView vacío.
  4. Escribe Log.d("CICLO", "onStart"); (y lo mismo en cada método del ciclo de vida). Filtra Logcat con tag:CICLO y observa el orden al abrir la app, al salir al escritorio, al volver y al girar el móvil.
