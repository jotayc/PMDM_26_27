Rama UD_2_8_action_menu

Menú de acción

Mantienes pulsado un botón y la barra de arriba se transforma: ahora ofrece opciones para ese botón. Con esta rama verás cómo se abre esa barra temporal, qué métodos llama Android mientras está abierta y cómo se deja lista para la próxima vez.

Violeta: simuladores; se manejan con los botones. En su registro, verde es un método al que llama Android y naranja, lo que hace tu código.

1

Qué vas a aprender

Una barra temporalUn menú que sustituye a la barra de app mientras se actúa sobre un elemento.
Pulsación largaEl listener para mantener pulsada una vista, y qué significa lo que devuelve.
El CallbackUn objeto con cuatro métodos a los que Android llama según lo que ocurre.
Controlar si está abiertoUn atributo que vale null mientras no hay ninguno abierto.

Al mantener pulsado el botón Action Menu, la barra de arriba cambia y ofrece tres colores. Al elegir uno, el botón cambia de color y la barra vuelve a ser la de siempre.

2

Conceptos

2.1Una barra que aparece solo cuando hace falta

Piensa en una aplicación de galería: mantienes pulsada una foto y, arriba, aparecen las opciones de compartir y borrar en lugar del título. Cuando terminas, la barra vuelve a ser la normal. Eso es un menú de acción: las opciones sobre un elemento ocupan durante un rato el sitio de la barra de app.

Android lo llama modo de acción, y por eso las clases y los métodos llevan ActionMode en su nombre.

Menú de la barraMenú de acción
Sobre qué actúaToda la pantallaUn elemento concreto
Cuándo se veSiempreDesde que se abre hasta que se cierra
Cómo se abreEstá ahí desde el principioDesde el código, normalmente con una pulsación larga

2.2La pulsación larga

Mantener pulsada una vista es un evento distinto del clic, con su propio listener: View.OnLongClickListener. La diferencia es que su método devuelve un valor.

onLongClick() devuelveSignifica
trueLa pulsación ya está atendida. Android no hace nada más con ella.
falseNo la he atendido. Android sigue como si este listener no existiera.

2.3El Callback: quien responde

Para abrir el menú se le pasa a Android un objeto de tipo ActionMode.Callback. Es una interfaz con cuatro métodos, y Android llama a cada uno cuando toca. Un callback es justo eso: código que escribes tú para que otro lo llame más tarde, igual que los listeners.

MétodoCuándo lo llama AndroidPara qué
onCreateActionMode()Al abrirseCrear las opciones y poner el título.
onPrepareActionMode()Justo después, y cada vez que se refrescaCambiar opciones sobre la marcha. Devuelve true si ha cambiado algo.
onActionItemClicked()Al pulsar una opciónHacer lo que corresponda.
onDestroyActionMode()Al cerrarseDejarlo todo listo para la próxima vez.
Abre el menú de acciónmira qué métodos se llaman

Mantén pulsado Action Menu en el móvil o usa el botón de la derecha. Después prueba las distintas formas de cerrarlo. El aspecto es aproximado.

mActionMode = null
No hay ningún menú de acción abierto.

    2.4Evitar abrirlo dos veces

    startSupportActionMode() devuelve el modo de acción que se acaba de abrir. La actividad lo guarda en un atributo, mActionMode. Mirando si vale null sabe si hay uno abierto y, si lo hay, no abre otro.

    Abrir, guardar; cerrar, poner a null

    Si onDestroyActionMode() no pusiera el atributo a null, seguiría pareciendo que hay uno abierto y el menú no volvería a abrirse nunca.

    El código paso a paso

    Abre la ventana TODO (View → Tool Windows → TODO): los comentarios van numerados del 1 al 9, y todos están en MainActivity.

    TODO 1Recordar si hay uno abierto

    MainActivity.java
    private ActionMode mActionMode;

    Como todo atributo de tipo objeto, empieza valiendo null.

    TODO 2-3Abrirlo con una pulsación larga

    Si no hay ninguno abierto, se abre, se guarda y se indica que la pulsación está atendida.

    MainActivity.java
    btn_action.setOnLongClickListener(new View.OnLongClickListener() {
    @Override
    public boolean onLongClick(View view) {
        boolean atendida = false;
        if (mActionMode == null) {
            mActionMode = startSupportActionMode(mActionCallback);
            atendida = true;
        }

        return atendida;
    }
});

    TODO 4El Callback en un atributo

    Es una clase anónima, como las de los listeners. Hasta ahora las escribías directamente como parámetro. Aquí es mucho más larga, así que se guarda la instancia en un atributo y el listener de arriba se lee mejor.

    MainActivity.java
    private ActionMode.Callback mActionCallback = new ActionMode.Callback() {
    // los cuatro métodos
};

    TODO 5Crear las opciones

    El inflater lo da el propio modo de acción. Devolver true es lo que hace que el menú se abra: con false, se cancela.

    MainActivity.java
    @Override
public boolean onCreateActionMode(ActionMode mode, Menu menu) {
    mode.getMenuInflater().inflate(R.menu.action_menu, menu);
    mode.setTitle("Action Menu");
    return true;
}

    TODO 6Preparar

    Aquí no se cambia nada, así que devuelve false. Hay que escribirlo igualmente, porque una interfaz obliga a implementar todos sus métodos.

    TODO 7-8Responder a la opción y cerrar

    Se compara el id de la opción con los del XML y se cambia el color. Con mode.finish() se cierra el menú: si no, seguiría abierto tras elegir.

    MainActivity.java
    @Override
public boolean onActionItemClicked(ActionMode mode, MenuItem item) {
    int itemId = item.getItemId();

    if (itemId == R.id.act_light_blue) {
        btn_action.setBackgroundColor(Color.CYAN);
    } else if (itemId == R.id.act_purple) {
        btn_action.setBackgroundColor(Color.MAGENTA);
    } else if (itemId == R.id.act_yellow) {
        btn_action.setBackgroundColor(Color.YELLOW);
    }

    mode.finish();
    return true;
}

    TODO 9Dejarlo listo

    MainActivity.java
    @Override
public void onDestroyActionMode(ActionMode mode) {
    mActionMode = null;
}

    El menú y el layout

    El fichero del menú, en la carpeta res/menu/. Aquí sí hay una barra, así que los iconos y app:showAsAction tienen efecto.

    res/menu/action_menu.xml
    <menu xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto">
    <item
        android:id="@+id/act_light_blue"
        android:icon="@drawable/fill_light_blue"
        android:title="Celeste"
        app:showAsAction="ifRoom|withText" />
    <item
        android:id="@+id/act_purple"
        android:icon="@drawable/fill_purple"
        android:title="Morado"
        app:showAsAction="ifRoom|withText" />
    <item
        android:id="@+id/act_yellow"
        android:icon="@drawable/fill_yellow"
        android:title="Amarillo"
        app:showAsAction="ifRoom|withText" />
</menu>

    El layout tiene dos botones, btn_action y btn_floating.

    El botón Menu flotante no hace nada en esta rama

    No tiene ningún listener. Ese botón y el fichero floating_menu.xml pertenecen al menú contextual flotante, que es otro tipo de menú y se trabaja en la rama UD_2_9_floating_menu.

    5

    Pruébalo

    1. Ejecuta la aplicación (Run) y haz un clic corto en Action Menu. No ocurre nada: solo tiene listener para la pulsación larga.
    2. Ahora mantenlo pulsado. La barra de app se cambia por la de acción, con el título «Action Menu», los iconos de color y una flecha a la izquierda.
    3. Pulsa uno de los colores. El botón cambia y vuelve la barra de siempre.
    4. Ábrelo otra vez y pulsa la flecha de la izquierda. Se cierra sin cambiar nada.
    5. Ábrelo otra vez y pulsa Atrás. Se cierra el menú, no la aplicación.
    6. Comenta la línea mActionMode = null y vuelve a ejecutar. Podrás abrir el menú una vez, pero ya no una segunda.

    Errores comunes

    Lo que pasaPor qué
    El menú se abre una vez y ya no vuelve a abrirseFalta poner mActionMode = null en onDestroyActionMode().
    Al elegir una opción, el menú sigue abiertoFalta mode.finish() en onActionItemClicked().
    El menú no se abreonCreateActionMode() devuelve false, o el listener está puesto en otro botón.
    La barra aparece sin opcionesFalta inflate() en onCreateActionMode().
    No compila startSupportActionMode() con tu CallbackSe ha importado android.view.ActionMode. Con AppCompatActivity hay que usar androidx.appcompat.view.ActionMode.
    Los id no se pueden usar en un switchLos id de los recursos no son constantes: se comparan con if.

    Para practicar

    Hazlo en tu propia rama para no modificar la del tema: git switch -c mio/UD_2_8.

    1. Pasa a strings.xml los títulos de las opciones y el título de la barra.
    2. Añade una cuarta opción que devuelva el botón a su color original.
    3. Haz que el título de la barra indique el botón que lo ha abierto.
    4. Añade un botón nuevo con su propia pulsación larga, que abra el mismo menú. Haz que la opción elegida cambie el color del botón que se pulsó.
    5. Muestra en onDestroyActionMode() un Toast que diga si se ha elegido un color o se ha cerrado sin elegir.
    6. Cambia onLongClick() para que abra el menú también con un clic corto. Piensa qué listener hace falta y por qué ya no devuelve nada.
