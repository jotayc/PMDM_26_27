Rama UD_2_7_menu_simple

Menú simple

Tres colores y una opción de aplicar en la barra de arriba de la aplicación. Con esta rama verás cómo se describe un menú en XML, cómo llega hasta la barra y cómo se responde cuando se pulsa una opción.

En la barra de arriba hay tres colores y una opción Aplicar. Pulsar un color lo deja elegido; pulsar Aplicar pinta el fondo de la pantalla con ese color.

2

Conceptos

2.1La barra de app y sus opciones

La barra de app es la franja superior de la pantalla, con el título. Además, puede mostrar opciones: unas se ven directamente en la barra, normalmente como un icono, y otras se guardan en el menú de desbordamiento, los tres puntos verticales.

Esta aplicación no tiene que añadir la barra a su layout, porque su tema ya la incluye. Basta con decirle qué opciones debe mostrar.

2.2El menú se describe en XML

Igual que un layout describe una pantalla, un fichero de menú describe unas opciones. Va en su propia carpeta, res/menu/, y su elemento raíz es <menu>, con un <item> por opción.

AtributoQué hace
android:idIdentifica la opción: es lo que se compara en Java para saber cuál se ha pulsado.
android:titleEl texto de la opción.
android:iconEl icono que se ve cuando la opción está en la barra.
android:orderInCategoryUn número para ordenarlas: la menor va primero.
app:showAsActionSi la opción se muestra en la barra o en el menú de desbordamiento.
Valor de app:showAsActionDónde aparece
ifRoomEn la barra si hay sitio; si no, en el menú de desbordamiento.
neverSiempre en el menú de desbordamiento.
alwaysSiempre en la barra. Úsalo con moderación, porque el espacio es limitado.
withTextSe combina con otro valor (ifRoom|withText) y pide mostrar también el texto si hay sitio.
ifRoom depende de la pantalla

Las cuatro opciones de esta rama llevan ifRoom, pero no siempre se ven igual. En un móvil en vertical suelen caber dos, y las otras quedan en el menú de desbordamiento. Al girarlo, la barra es más ancha y caben todas.

app:, no android:

Se escribe app:showAsAction, con el espacio de nombres app. Con android:showAsAction compila, pero en esta actividad no tiene efecto, y la opción acaba en el menú de desbordamiento.

2.3Inflar: del XML a las opciones

Inflar significa leer un fichero XML y crear los objetos que describe. La actividad no sabe nada del menú hasta que lo infla, y lo hace en un método que Android llama por sí solo.

La barra y su menúcambia el XML y pulsa las opciones

Elige el valor de app:showAsAction de cada opción y gira el móvil para ver qué cabe en la barra. Después pulsa un color y luego Aplicar. El aspecto es aproximado.

selectedColor = WHITE
    Dos métodos, dos momentos

    onCreateOptionsMenu() crea las opciones; onOptionsItemSelected() responde cuando se pulsa una. Una sola actividad, un solo método para todas las opciones: dentro se distingue cuál ha sido por su id.

    El código paso a paso

    Abre la ventana TODO (View → Tool Windows → TODO): los comentarios van numerados del 1 al 9, y todos están en MainActivity.

    TODO 1-2Los atributos

    El color elegido tiene que estar en un atributo porque se escribe en una pulsación (un color) y se lee en otra (Aplicar). Una variable local desaparecería al terminar el método. El layout tiene un id en su vista raíz para poder cambiarle el fondo.

    MainActivity.java
    private ConstraintLayout constraintLayout;
int selectedColor = Color.WHITE;

constraintLayout = (ConstraintLayout) findViewById(R.id.root_const_lay);

    TODO 3-4Crear el menú

    Android le pasa al método un menú vacío, y inflate() lo llena con las opciones del XML. Devolver true indica que el menú debe mostrarse.

    MainActivity.java
    @Override
public boolean onCreateOptionsMenu(Menu menu) {
    getMenuInflater().inflate(R.menu.simple_menu,menu);

    return true;
}

    TODO 5-6Saber qué opción se ha pulsado

    El método recibe la opción como un MenuItem, y su id se compara con los del XML, con if. Los id de recursos no se pueden usar en un switch, porque no son constantes.

    MainActivity.java
    @Override
public boolean onOptionsItemSelected(@NonNull MenuItem item) {
    int itemId = item.getItemId();
    // comparaciones y return
}

    TODO 7-8Elegir y aplicar

    Un color no pinta nada: solo se guarda y avisa con un Toast. Es Aplicar quien usa el color guardado.

    MainActivity.java
    if (itemId == R.id.item_blue) {
    selectedColor = Color.BLUE;
    myToast("Azul seleccionado");
} else if (itemId == R.id.item_green) {
    selectedColor = Color.GREEN;
    myToast("Verde seleccionado");
} else if (itemId == R.id.item_red) {
    selectedColor = Color.RED;
    myToast("Rojo seleccionado");
} else if (itemId == R.id.item_apply) {
    constraintLayout.setBackgroundColor(selectedColor);
}

    TODO 9Opción atendida

    Aquí se devuelve siempre true, porque todas las opciones son nuestras. Cuando una actividad pueda recibir opciones que no son suyas, lo correcto es return super.onOptionsItemSelected(item); para las demás, como se ve en la teoría de la UD2.

    El menú y el layout

    Los colores llevan su icono, en res/drawable/. Aplicar no tiene, así que, cuando cabe en la barra, se ve su texto.

    res/menu/simple_menu.xml
    <menu xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto">
    <item
        android:id="@+id/item_red"
        android:icon="@drawable/color_red"
        android:orderInCategory="1"
        android:title="Rojo"
        app:showAsAction="ifRoom|withText" />
    <item
        android:id="@+id/item_green"
        android:icon="@drawable/color_green"
        android:orderInCategory="2"
        android:title="Verde"
        app:showAsAction="ifRoom" />
    <item
        android:id="@+id/item_blue"
        android:icon="@drawable/color_blue"
        android:orderInCategory="3"
        android:title="Azul"
        app:showAsAction="ifRoom" />
    <item
        android:id="@+id/item_apply"
        android:orderInCategory="4"
        android:title="Aplicar"
        app:showAsAction="ifRoom" />
</menu>

    El layout está vacío: no tiene ninguna vista, solo un id en la vista raíz para poder cambiarle el color de fondo.

    res/layout/activity_main.xml
    <androidx.constraintlayout.widget.ConstraintLayout
    android:id="@+id/root_const_lay"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    tools:context=".MainActivity">

</androidx.constraintlayout.widget.ConstraintLayout>
    5

    Pruébalo

    1. Ejecuta la aplicación (Run) con el móvil en vertical. La pantalla está en blanco y en la barra hay dos colores y los tres puntos. Púlsalos: dentro están las otras dos opciones, solo con su texto.
    2. Pulsa Aplicar sin haber elegido nada. El fondo se pinta de blanco, el valor inicial de selectedColor, así que no se nota.
    3. Pulsa el rojo. Aparece el Toast, pero el fondo no cambia. Pulsa Aplicar y ahora sí.
    4. Mantén pulsado un icono de la barra. Aparece su title: por eso hay que ponérselo siempre, aunque no se lea en la barra.
    5. En el XML, cambia a never el app:showAsAction de Rojo y vuelve a ejecutar. Rojo pasa al menú de los tres puntos y su sitio en la barra lo ocupa la siguiente opción.
    6. Gira el móvil con un color aplicado. Ahora caben las cuatro opciones en la barra, pero el fondo vuelve a ser blanco: la actividad se crea de nuevo y sus atributos vuelven a su valor inicial.

    Errores comunes

    Lo que pasaPor qué
    La barra no muestra ninguna opciónFalta inflate(), o onCreateOptionsMenu() devuelve false.
    R.menu.simple_menu sale en rojoEl fichero no está en res/menu/ o tiene otro nombre.
    Las opciones aparecen, pero no hacen nadaEl método está mal escrito y no sobrescribe el original. Con @Override el compilador lo avisa.
    Una opción no sale en la barra aunque hay sitioSe ha escrito android:showAsAction en lugar de app:showAsAction.
    Falta el prefijo app:El elemento <menu> no declara xmlns:app.
    El fondo no cambia al pulsar un colorEs lo esperado: un color solo se guarda. El fondo cambia al pulsar Aplicar.

    Para practicar

    Hazlo en tu propia rama para no modificar la del tema: git switch -c mio/UD_2_7.

    1. Pasa a strings.xml los títulos de las opciones.
    2. Añade una opción Blanco y otra Sobre esta app; esta última, con never, que muestre un Toast con tu nombre.
    3. Haz que los colores se apliquen directamente al pulsarlos y quita la opción Aplicar.
    4. Agrupa los tres colores en un submenú: un <item> Colores con otro <menu> dentro.
    5. Cambia el final del método para que las opciones atendidas devuelvan true y el resto super.onOptionsItemSelected(item).
    6. Añade un TextView al layout que muestre el nombre del color elegido.
