Guía de Android Studio

Todo lo que rodea al código: las partes de Android Studio, qué es cada fichero del proyecto, cómo se construye y cómo se ejecuta la aplicación. Vuelve aquí siempre que no recuerdes dónde está algo.

1

La ventana de Android Studio

Android Studio organiza su ventana en zonas. Cada número del esquema corresponde a una fila de la tabla.

ZonaPara qué sirve
1Barra principalMenú (☰), nombre del proyecto, rama de Git en la que estás, configuración de ejecución (app), dispositivo donde se ejecutará y los botones Run y Debug.
2Barra de ventanas izquierdaAbre y cierra las ventanas de la izquierda: Project, Commit, Resource Manager…
3Ventana ProjectLos ficheros del proyecto (apartado 2).
4EditorUn fichero por pestaña. En los layouts XML aparecen los modos Code, Split y Design.
5Barra de ventanas derechaGradle, Device Manager (dispositivos virtuales) y Running Devices (donde se ve el emulador).
6Ventanas inferioresLogcat (mensajes de la aplicación), Terminal, Build (resultado de compilar), TODO (lista de comentarios TODO) y Problems.
7Barra de estadoRuta del fichero abierto y tareas en curso, como la sincronización de Gradle.
Si no encuentras una ventana

Todas están en View → Tool Windows.

2.2Lo que no está en el repositorio

Hay ficheros que ves en tu carpeta pero que no se suben a GitHub, porque son de tu equipo y cada uno tiene los suyos:

3

Los ficheros clave

3.1AndroidManifest.xml: la ficha de la aplicación

Android lo lee para saber cómo se llama la aplicación, qué icono tiene, qué pantallas la forman y cuál se abre al pulsar el icono. Esta es la parte principal del de este proyecto (resumida):

app/src/main/AndroidManifest.xml
<application
    android:icon="@mipmap/ic_launcher"
    android:label="@string/app_name"
    android:theme="@style/Theme.PMDM">
    <activity
        android:name=".MainActivity"
        android:exported="true">
        <intent-filter>
            <action android:name="android.intent.action.MAIN" />
            <category android:name="android.intent.category.LAUNCHER" />
        </intent-filter>
    </activity>
</application>
  • Cada pantalla (activity) tiene que estar declarada aquí.
  • MAIN y LAUNCHER marcan la pantalla que se abre al pulsar el icono.
  • @string/app_name y @mipmap/ic_launcher son referencias a recursos de res/.

3.2activity_main.xml: el diseño de la pantalla

Describe en XML qué elementos (vistas) tiene la pantalla y cómo se colocan. En este proyecto el contenedor principal es un ConstraintLayout: cada vista se sujeta a los bordes o a otras vistas mediante restricciones.

3.3MainActivity.java: el código de la pantalla

app/src/main/java/com/example/pmdm/MainActivity.java
public class MainActivity extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);                 // pantalla completa
        setContentView(R.layout.activity_main);  // muestra el layout
    }
}
  • Extiende AppCompatActivity: es una actividad, es decir, una pantalla.
  • onCreate() se ejecuta al crearse la pantalla: aquí se prepara todo.
  • setContentView() indica qué layout se muestra.

3.4res/values: textos, colores y temas

strings.xmlTodos los textos, cada uno con un nombre. En XML se usan con @string/nombre y en Java con R.string.nombre.
colors.xmlLos colores con nombre.
themes.xmlEl aspecto general de la aplicación. values-night/ tiene la versión para el modo oscuro.

Gradle: cómo se construye la aplicación

Android Studio incluye todo lo necesario para desarrollar:

Gradle es la herramienta que convierte el proyecto en una aplicación instalable (un fichero APK):

4.1Los ficheros de Gradle

FicheroQué define
settings.gradleNombre del proyecto y módulos que lo forman (aquí, solo app).
build.gradlePlugins comunes a todos los módulos.
app/build.gradleNombre del paquete (namespace), versiones de Android y librerías que usa la aplicación (dependencies).
gradle/libs.versions.tomlLas versiones de las librerías y plugins, reunidas en un solo sitio.
gradle/wrapper/…propertiesLa versión exacta de Gradle: así todos compilamos con la misma.
gradle.propertiesOpciones generales de Gradle.

4.2Las tres versiones de Android

minSdkVersión mínima de Android en la que se puede instalar la aplicación.
targetSdkVersión para la que está preparada: Android le aplica las reglas de esa versión.
compileSdkVersión con la que se compila: qué clases y métodos existen.
Importante

Cuando cambia un fichero de Gradle, Android Studio pide sincronizar: pulsa Sync Now (o el icono del elefante, Sync Project with Gradle Files). No cambies las versiones del proyecto: están fijadas para que todos tengamos exactamente lo mismo.

Ejecutar la aplicación

5.1En el emulador

  1. Abre el Device Manager (barra derecha, o View → Tool Windows → Device Manager).
  2. Pulsa + → Create Virtual Device, elige un modelo y una imagen del sistema reciente.
  3. Elige el dispositivo en la barra principal y pulsa Run (Mayús+F10).
Virtualización

El emulador necesita la virtualización activada en la BIOS (Intel VT-x o AMD-V). Consume bastante memoria: ciérralo cuando no lo uses.

5.2En tu móvil

  1. En Ajustes → Información del teléfono, pulsa siete veces sobre Número de compilación.
  2. En Ajustes → Sistema → Opciones para desarrolladores, activa Depuración USB.
  3. Conecta el móvil por USB y acepta el aviso que aparece en su pantalla.
  4. Elige el móvil en el selector de dispositivos y pulsa Run.

En Windows puede hacer falta el controlador USB del fabricante. Desde Android 11 también se puede depurar por Wi-Fi (Depuración inalámbrica).

Logcat y el depurador

6.1Logcat

Muestra los mensajes que genera la aplicación mientras se ejecuta, también los errores. Puedes escribir los tuyos con la clase Log:

MainActivity.java
Log.d("MainActivity", "Se ha pulsado el botón");

En la ventana Logcat, escribe tag:MainActivity en el filtro para ver solo tus mensajes.

Si la aplicación se cierra sola

El error aparece en rojo en Logcat. Busca la primera línea que menciona una clase tuya: ahí está el fallo.

6.2El depurador

  1. Haz clic en el margen izquierdo del editor, junto a una línea: aparece un punto de ruptura.
  2. Ejecuta con Debug (Mayús+F9). La aplicación se detiene al llegar a esa línea.
  3. En la ventana Debug ves el valor de cada variable.
  4. Avanza con F8 (siguiente línea), F7 (entrar en el método) o F9 (continuar).

Ciclo de vida de una actividad

Cada pantalla pasa por varios estados, y en cada cambio Android llama a un método de la actividad:

MétodoCuándo se llama
onCreate()Al crearse la actividad. Se prepara la interfaz. Obligatorio.
onStart()La actividad va a hacerse visible.
onResume()Está visible y el usuario ya puede usarla.
onPause()Otra ventana se pone delante y pierde el foco.
onStop()Deja de verse. Buen momento para guardar datos.
onRestart()Vuelve a mostrarse tras estar parada.
onDestroy()Se destruye y libera su memoria.

Las actividades abiertas se guardan en una pila: la que se ve es la de arriba, y al pulsar Atrás se quita y vuelve a verse la anterior.
