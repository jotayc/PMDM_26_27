Rama UD_3_2_SQLite

SQLite

Una pequeña aplicación que guarda ciudades en una base de datos dentro del móvil. Con esta rama verás cómo se crea esa base de datos, cómo se actualiza sin perder datos cuando cambian sus tablas y cómo se insertan y se consultan filas.

Qué vas a aprender

Crear la base de datosLa clase que la crea la primera vez y la actualiza cuando cambia.
VersionesCómo cambiar las tablas sin perder los datos de quien ya tiene la aplicación.
InsertarGuardar una fila con ContentValues e insert().
ConsultarPedir filas con query() y recorrerlas con un cursor.

La aplicación tiene tres campos para una ciudad, su población y su superficie. Insertar la guarda en la base de datos y Mostrar enseña la primera ciudad de la tabla.

2

Conceptos

2.1Una base de datos dentro de la aplicación

SQLite es una base de datos relacional que viene incluida en Android. No hay servidor: toda la base de datos es un fichero dentro de la aplicación. Se usa para datos con estructura, como una lista de ciudades, cuando no bastan unos pares clave-valor.

Esta rama usa tres clases de Android:

ClasePara qué
SQLiteOpenHelperCrea la base de datos y la actualiza. De ella hereda DBAccess.
SQLiteDatabaseLa conexión abierta: con ella se insertan y se consultan datos.
CursorEl resultado de una consulta, que se recorre fila a fila.

Y la aplicación tiene dos clases propias: DBAccess, con todo lo que toca la base de datos, y MainActivity, que solo llama a sus métodos y nunca escribe SQL.

Hoy en día

La documentación de Android recomienda usar Room, una biblioteca que funciona sobre SQLite, porque estas clases son de bajo nivel: el SQL no se comprueba al compilar y hay que escribir mucho código repetitivo. Aquí se usan directamente para entender qué ocurre por debajo. También recomienda abrir la base de datos fuera del hilo principal; este ejemplo no lo hace, para no complicarlo.

2.2Las versiones de la base de datos

Imagina que publicas tu aplicación y después necesitas otra columna. Los usuarios que ya la tienen guardan sus datos en la tabla antigua: no puedes borrarla, y onCreate() no se va a ejecutar, porque la base de datos ya existe. Por eso cada base de datos tiene un número de versión.

Actualiza la base de datoselige de qué versión viene el usuario

Un móvil tiene instalada una versión antigua de la aplicación y el usuario la actualiza a la que tiene DB_VERSION = 3. Elige la versión de partida y mira qué ejecuta el switch.

Columnas de la tabla
    Cada cambio, en dos sitios

    onCreate() crea la última versión, para los usuarios nuevos. onUpgrade() lleva a la última versión a quienes ya tienen la aplicación. Si cambias la tabla y olvidas uno de los dos, la aplicación falla solo a una parte de los usuarios.

    El código paso a paso

    Abre la ventana TODO (View → Tool Windows → TODO): los comentarios van numerados del 1 al 25. Del 1 al 21 están en Resources/DBAccess.java, y del 22 al 25, en controllers/MainActivity.java.

    TODO 1-3La clase y su constructor

    DBAccess.java
    public class DBAccess extends SQLiteOpenHelper {

    private static final String DB_NAME = "db_dam";
    private static final int DB_VERSION = 3;

    public DBAccess(Context context) {
        super(context, DB_NAME, null, DB_VERSION);
    }

    El constructor le pasa a la clase padre el contexto, el nombre del fichero y la versión. El tercer parámetro es para casos avanzados y normalmente es null. Los nombres de la tabla y de las columnas también están en constantes: así solo se escriben una vez.

    TODO 4-6onCreate(): crear la tabla

    DBAccess.java
    @Override
public void onCreate(SQLiteDatabase sqLiteDatabase) {
    String CREATE_USER_TABLE =  "CREATE TABLE " +DB_TABLE_NAME+ "("
            +CITY_COLUMN+ " TEXT,"
             + POBLATION_COLUMN + " INTEGER,"
            + SURFACE_COLUMN + " REAL" + ")";

    sqLiteDatabase.execSQL(CREATE_USER_TABLE);
}

    La sentencia es SQL normal, construida como un String. Una vez sustituidas las constantes queda así:

    SQL que se ejecuta
    CREATE TABLE db_ciudades(cityName TEXT,poblation INTEGER,surface REAL)

    execSQL() ejecuta una sentencia que no devuelve filas. Los comentarios del código enseñan cómo era esta sentencia en las versiones 1 y 2.

    TODO 7-8onUpgrade(): el switch sin break

    DBAccess.java
    @Override
public void onUpgrade(SQLiteDatabase sqLiteDatabase, int oldVersion, int newVersion) {
    switch(oldVersion){
        case 1:
            sqLiteDatabase.execSQL("ALTER TABLE " + DB_TABLE_NAME  +" ADD COLUMN " + POBLATION_COLUMN +" INTEGER");
        case 2:
            sqLiteDatabase.execSQL("ALTER TABLE " + DB_TABLE_NAME  +" ADD COLUMN " + SURFACE_COLUMN +" REAL");
    }
}
    Aquí la falta de break es a propósito

    Un switch sin break sigue ejecutando los case siguientes. Es justo lo que se necesita: el usuario empieza en la versión que tiene y aplica, en orden, todos los cambios que le faltan. Con un break, quien viene de la versión 1 se quedaría sin la columna surface.

    ALTER TABLE ... ADD COLUMN añade una columna sin tocar las filas que ya existen.

    TODO 9-13Insertar una fila

    DBAccess.java
    SQLiteDatabase db = this.getWritableDatabase();

ContentValues values = new ContentValues();
values.put(CITY_COLUMN, city);
values.put(POBLATION_COLUMN, poblation);
values.put(SURFACE_COLUMN, superficie);

result = db.insert(DB_TABLE_NAME,null,values);

db.close();
    PasoQué hace
    getWritableDatabase()Abre la conexión para escribir. Es aquí, la primera vez, cuando se ejecuta onCreate() u onUpgrade().
    ContentValuesGuarda los datos de la fila como pares columna-valor. No hay que escribir SQL ni preocuparse de las comillas.
    insert(tabla, null, valores)Inserta la fila. Devuelve su número, o -1 si ha fallado.
    close()Cierra la conexión.

    TODO 14-19Consultar: la primera ciudad

    DBAccess.java
    SQLiteDatabase db = this.getReadableDatabase();
String[] cols = new String[]{ CITY_COLUMN };

Cursor cursor = db.query(DB_TABLE_NAME,cols,null,null,null,null,null);
if(cursor.moveToFirst()) {
    result = cursor.getString(0);
}

cursor.close();
db.close();
    Parámetro de query()Equivale en SQL aAquí
    1. La tablaFROMDB_TABLE_NAME
    2. Las columnasSELECTcols: solo la ciudad
    3 y 4. La condición y sus argumentosWHEREnull: todas las filas
    5. El agrupamientoGROUP BYnull
    6. La condición del grupoHAVINGnull
    7. El ordenORDER BYnull

    getString(0) lee la columna 0 del resultado, no de la tabla: la posición corresponde al array cols, que aquí solo tiene una.

    TODO 20-21Recorrer todas las filas

    getAllCities() no se usa en la pantalla, pero es el patrón que vas a necesitar casi siempre:

    DBAccess.java
    if(cursor.moveToFirst()){
    do{
        resultCities.add(cursor.getString(0));
    }while(cursor.moveToNext());
}

    Los comentarios de ese método enseñan cómo se filtraría con una condición: cada ? se sustituye por un valor del array de argumentos. Es la forma correcta de meter en una consulta un dato escrito por el usuario, porque Android lo trata como un valor y no como parte de la sentencia.

    TODO 22Crear el acceso en la actividad

    MainActivity.java

mDB.getVersionDB();

    Crear el objeto no abre nada: la base de datos se abre al pedir acceso, y aquí eso ocurre dentro de getVersionDB().

    TODO 23-24Insertar desde el botón

    MainActivity.java
    if(city.isEmpty() || textoPobl.isEmpty() || textoSurf.isEmpty()){
    myToast("Rellena los tres campos");
    return;
}

int pobl    = Integer.parseInt(textoPobl);

    Un EditText siempre da texto, pero las columnas son números, así que hay que convertirlo. parseInt() con un texto vacío lanza una excepción que cerraría la aplicación: por eso se comprueba antes. El inputType del layout (number y numberDecimal) evita además que se puedan escribir letras.

    TODO 25Mostrar la primera ciudad

    getFirstCity() devuelve null cuando la tabla está vacía, y la actividad lo comprueba antes de usarlo.

    Lo que este ejemplo simplifica

    Como indica la cabecera de MainActivity, la tabla no tiene clave primaria y solo se muestra una ciudad. Además, no hay una clase Ciudad: los datos viajan sueltos. En una aplicación real estas tres cosas se harían de otra forma, y las tienes en «Para practicar».

    Pruébalo

    1. Ejecuta la aplicación (Run) y pulsa Mostrar. La tabla está vacía, así que aparece el aviso de que no se ha podido recuperar.
    2. Pulsa Insertar con los campos vacíos. Aparece «Rellena los tres campos».
    3. Rellena los tres campos y pulsa Insertar. Después, Mostrar: aparece tu ciudad.
    4. Inserta otra ciudad y pulsa Mostrar. Sigue saliendo la primera, porque es lo que hace el método.
    5. Cierra la aplicación del todo y ábrela. Al pulsar Mostrar, los datos siguen ahí.
    6. Abre la base de datos con View → Tool Windows → App Inspection, pestaña Database Inspector. Ahí está la tabla con todas sus filas.
    7. Abre Logcat y filtra por tag:DB. Verás «Tablas creadas» solo la primera vez que se instala la aplicación.

    Errores comunes

    Lo que pasaPor qué
    no such column después de cambiar el CREATE TABLELa base de datos ya existía y onCreate() no se vuelve a ejecutar. Sube DB_VERSION y añade el cambio en onUpgrade(). Mientras desarrollas también puedes desinstalar la aplicación.
    Se cierra con SQLiteException al abrir, tras bajar DB_VERSIONLa versión no puede bajar: Android no sabe volver atrás. Vuelve a subirla o desinstala la aplicación.
    Quien viene de una versión antigua no tiene todas las columnasHay un break en el switch de onUpgrade().
    CursorIndexOutOfBoundsException al leerSe ha leído sin mover el cursor, o sin comprobar que moveToFirst() ha devuelto true.
    NumberFormatException al insertarSe ha convertido a número un texto vacío o no numérico.
    En el Database Inspector, 88.02 aparece como 88.0199966La superficie se trata como float, un tipo que guarda los decimales de forma aproximada. Con double la aproximación es mucho menor.
    Error de SQL al crear la tablaFaltan comas o espacios al concatenar el String. Míralo en Logcat, donde aparece la sentencia completa.

    Para practicar

    Hazlo en tu propia rama para no modificar la del tema: git switch -c mio/UD_3_2.

    1. Cambia Mostrar para que enseñe todas las ciudades, con getAllCities().
    2. Añade a la consulta la población y la superficie, y muéstralas junto a la ciudad. Fíjate en las posiciones de getInt() y getFloat().
    3. Añade una columna gentilicio de tipo TEXT: sube la versión a 4, cambia onCreate() y añade su case 3. Comprueba con el Database Inspector que los datos anteriores siguen ahí.
    4. Haz que las ciudades salgan ordenadas por nombre, usando el parámetro de ORDER BY de query().
    5. Crea un método que busque por nombre, con ? y su array de argumentos, y úsalo desde un botón nuevo.
    6. Crea un método que borre una ciudad por su nombre, con db.delete(), y otro que cambie su población, con db.update().
    7. Crea una clase Ciudad y haz que getAllCities() devuelva una lista de ciudades. Muéstralas en un RecyclerView.
